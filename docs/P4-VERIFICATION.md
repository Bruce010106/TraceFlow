3. 供应商第一次请求保持未返回。文档已经持久化，作业处于 RUNNING，后台持续续租。
4. 验证 JVM PID 和启动参数属于本次实例后，强制终止 PID 4776，没有执行优雅关闭回调。
5. 另一进程立即从 PostgreSQL 读到同一个文档和 RUNNING 作业，待审建议数为 0。
6. 启动全新 JVM，不提交人工重试请求。新进程发现租约过期，将第一次尝试标为 EXPIRED，退避后发起第二次。
