## 安全与并发边界

`SecurityIntegrationTest` 通过实际认证端点生成会话，保留完整 Spring Security 过滤链，覆盖：

- 匿名业务访问401；写入缺失CSRF时403；登录会话ID及CSRF轮换；退出销毁会话；错误凭据不区分用户是否存在。
- 注册字段校验、用户名大小写归一、重复账号409、BCrypt密码校验；响应不包含密码散列；多字节密码不会越过72字节限制。
- OWNER/EDITOR/VIEWER/非成员的项目、文档、建议、任务、历史和成员接口矩阵，包括已应用建议和重复导入的幂等返回路径。
- 编辑者完成导入、审核和更新，实际账号写入文档与历史；VIEWER只读，非成员404隐藏资源存在性。
- 使用原会话降级/移除成员后立即生效；已应用建议重放也必须重新授权，不增加历史。
- 写请求等待项目锁时，撤权事务先提交，写请求获得锁后被拒绝，数据库没有新增文档。
- 导入者退出后系统队列继续抽取，仅生成PENDING建议，仍需当前有权限用户确认。
- 有权限用户的版本冲突保留PENDING，重审成功；旧的已应用建议重放返回原快照。
- 旧项目默认不公开；显式本机认领只分配无成员项目，重复执行不重复授权、不覆盖已有所有者，未知账号失败不写入。

原有P0–P4测试在认证过滤链下继续运行：文档/审核幂等、并发任务版本、事务回滚、快照冻结、SKIP LOCKED、租约续期/到期、旧token fencing、退避与预算、优雅关闭及后台故障恢复均保持通过。P5没有重新执行P4的Java进程硬杀实验；该历史实测见P4验收记录。

## 联调发现并修复

首次浏览器切换账号时，服务端登录成功但页面停留登录界面。原因是直接 `queryClient.clear()` 删除了仍被观察的身份查询。已改为取消旧请求、移除业务查询和mutation缓存，保留 `me` 查询订阅，再显式更新身份；请求增加认证代次检查，防止旧请求迟到的401覆盖新的登录。最终JAR已重跑所有者→未授权账号→所有者→只读账号的切换，以及会话失效后重新登录，均通过。
