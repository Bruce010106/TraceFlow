# P3：DeepSeek 自然语言抽取

## 范围与运行

P3 默认使用 DeepSeek 的 Chat Completions API，输出 JSON 后经服务端校验生成待审建议。模型不能直接创建或修改任务。

在 PowerShell 7 的项目根目录，配置以下环境变量，或填写被 Git 忽略的 .local/ai.properties：

    DEEPSEEK_API_KEY=<本机密钥>

默认参数：base URL=https://api.deepseek.com，model=deepseek-flash，response_format=json_object，max_tokens=4096，thinking.type=disabled。可配置；不是把某个模型名写死在 Java 实现中。

两个终端运行：

    ./scripts/Start-Backend.ps1 -Temporary
    ./scripts/Start-Frontend.ps1

前端 http://127.0.0.1:5173，后端默认 http://127.0.0.1:8091。临时库退出后不保留数据；持久化数据库配置见 README。修改模型配置后重启后端。

仅在需要确定性离线演示时运行 ./scripts/Start-Backend.ps1 -Temporary -Mock。真实模型失败不会回退到模拟建议。

## 从原文到任务

1. 导入事务锁定项目、计算原有去重键、保存不可变原文和 RUNNING 作业，以及当时的任务快照。
2. 事务提交后调用模型。输入仅含当前项目最多 50 个未归档任务、记录日期/时区和带行号原文。单次调用有总超时及 256 KiB 响应体上限；不自动重试、不跟随重定向。
3. 校验完整 JSON、字段白名单、日期、建议数量（最多 20）、引用任务是否在快照、行号及逐字引句。任一建议不合法时，本次全部建议不入库。
4. 新的短事务原子保存所有 PENDING 建议并完成作业。UPDATE 的基准版本来自模型调用前的任务快照。模型只指定明确修改的字段，其余值从快照补齐。
5. 人工审核、修订、拒绝或确认，沿用原有审核事务。完整字段替换、重复确认返回第一次应用结果、409 后保留 PENDING 的行为不变。

JSON 模式只能保证 JSON 形式，字段事实和语义仍可能错误。引用/格式校验不能证明模型的理解正确，仍需要人工核对。相对日期以记录日期计算，界面继续展示推断日期供核对。

## 幂等与失败

- 去重键仍是项目 + 换行规范化原文哈希 + 记录日期 + 时区。改变标题不会触发新模型调用。
- 并发导入同一文档只由第一个请求发起抽取，其他请求返回相同文档和 RUNNING 状态。界面会轮询更新。
- 抽取失败时原文和 FAILED 作业保留，任务不变、没有半批建议。导入 HTTP 200 表示原文已接收，不代表抽取成功；应读取 jobs 最后一项的 status。
- 明确点击“重新抽取”调用 POST /api/documents/{id}/extract。仅 FAILED 文档创建新尝试；RUNNING/SUCCEEDED 返回原记录，不产生重复尝试。
- 每次重试保留旧作业，使用当前模型配置及新的项目任务快照；不会覆盖既有审核建议。
- 模型服务 401/403、429、5xx、超时、空响应、截断或不合法 JSON 都保存安全错误码，不返回原始供应商错误体、鉴权头或 API Key。
- 当前同步调用会跨两个短事务运行。进程崩溃后遗留 RUNNING 作业的自动恢复、持久化队列、租约和退避重试属于 P4，本阶段没有承诺崩溃恢复或供应商计费的严格 exactly-once。

## 数据与接口

V2 迁移在 extraction_job 增加 provider、resolved_model、response_id、input_tokens、output_tokens、duration_ms、completed_at、output_json，并为每份文档的 RUNNING/SUCCEEDED 作业分别增加部分唯一索引。原六张业务表保留。

作业保存模型名、提示版本、输入任务快照和成功输出；成功抽取的用量来自供应商返回值，不估算金额。原文及审核决定仍通过建议、任务历史关联。

- GET /api/health：extractor、provider、model、configured、promptVersion，不暴露密钥。
- GET /api/projects/{id}/documents：新增 extraction_status、extraction_error。
- POST /api/documents/{id}/extract：显式重试失败抽取。
- 原有文档导入、建议审核、任务与历史接口保持路径和写入契约。

## 可配置项

| 环境变量 | 默认值 |
| --- | --- |
| TRACEFLOW_AI_MODE | llm；可显式设为 mock |
| TRACEFLOW_AI_BASE_URL | https://api.deepseek.com |
| TRACEFLOW_AI_MODEL | deepseek-flash |
| TRACEFLOW_AI_API_KEY / DEEPSEEK_API_KEY | 无；仅后端读取 |
| TRACEFLOW_AI_RESPONSE_FORMAT | json_object；也支持 json_schema |
| TRACEFLOW_AI_TOKEN_LIMIT_FIELD | max_tokens；也支持 max_completion_tokens |
| TRACEFLOW_AI_THINKING_MODE | disabled；其他协议可设 provider_default 省略该参数 |
| TRACEFLOW_AI_TIMEOUT_SECONDS | 45，范围 1–90 |
| TRACEFLOW_AI_MAX_TOKENS | 4096，范围 256–8192 |

使用其他 OpenAI 兼容服务时，需按该服务支持的字段调整以上参数。远端地址要求 HTTPS，回环本地推理服务允许 HTTP。JSON schema 模式必须由模型服务支持，不会自动降级。

## 测试

mvn -s .mvn/central-settings.xml test

默认回归仅使用独立临时 PostgreSQL 与本机 HTTP 测试服务，不会使用或消耗真实 API Key。WorkflowIntegrationTest 显式使用离线抽取；LlmWorkflowIntegrationTest 使用真实 HTTP 适配器与受控响应，覆盖调用与数据库事务的边界；OpenAiExtractorTest/ProposalValidatorTest 覆盖格式、超时和输入校验。

真实 DeepSeek 的浏览器验收另记于 P3-VERIFICATION.md。只有实际调用成功后才记录为真实模型通过。
