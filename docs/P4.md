# P4：PostgreSQL 后台抽取队列

## 使用与结果

导入接口在同一个短事务中保存不可变原文、任务快照和 QUEUED 作业，然后返回 HTTP 202。后台工作线程独立领取并调用模型；关闭或切换页面不会取消作业。页面轮询 QUEUED、RUNNING、RETRY_WAIT，显示预计重试时间与各次尝试记录。

运行方式与 P3 相同，根目录两个终端：

    ./scripts/Start-Backend.ps1 -Temporary
    ./scripts/Start-Frontend.ps1

默认开启两个工作线程。默认真实模型为已配置的 DeepSeek；密钥仍仅放后端环境变量或被 Git 忽略的 .local/ai.properties。

临时数据库用于演示，退出宿主后不保留数据。需要跨完整服务/机器重启保留队列时，使用 README 中的独立持久化 PostgreSQL，去掉 -Temporary。队列不依赖内存、Redis 或外部消息中间件。

## 作业与尝试

- extraction_job 表示一轮抽取，generation 表示用户发起的轮次。
- extraction_attempt 追加记录每次领取、调用结果或中断，attempt_no 从 1 开始。
- 每轮默认最多 3 次自动尝试；人工仅能对 FAILED 文档创建新一轮，并捕获新的任务快照。
- 自动重试保留同一轮最初的文档和任务快照，避免重试时悄悄改变任务匹配依据。
- 一份文档最多一个活跃作业（QUEUED/RUNNING/RETRY_WAIT），最多一个成功作业；由 PostgreSQL 部分唯一索引约束。

状态流：

    QUEUED -> RUNNING -> SUCCEEDED -> 人工审核
                  |-> RETRY_WAIT -> RUNNING
                  |-> FAILED -> 用户明确发起新一轮 QUEUED

租约到期记为 attempt.EXPIRED；服务优雅停止记为 attempt.ABANDONED。作业根据剩余次数进入 RETRY_WAIT 或 FAILED。FAILED 是终态，不会被轮询器无限复活。

## 数据库与租约协议

领取使用 SELECT ... FOR UPDATE SKIP LOCKED，按 next_run_at、创建时间和 ID 排序，在短事务内领取一条作业、递增 attempt_count、生成全新的 lease_token、设置 lease_until 并插入尝试记录。多个同配置实例可以共享数据库；内存线程池仅限制本实例并发数。

网络调用在事务外进行。默认租约 30 秒，每 5 秒用独立线程续租，因此长模型调用不会长期持有项目锁。

续租锁行使用 SKIP LOCKED，避免在结果提交的行锁后等待，再把已经到期的租约复活。续租失败或临时无法访问数据库不代表可以无条件写入：最终结果仍必须通过数据库中的令牌和期限校验。

成功提交按“项目 -> 作业”顺序加锁，与审核事务保持一致；检查当前 RUNNING 状态、lease_token 和未过期的 lease_until。所有建议插入后再次校验令牌和期限，再原子完成作业及尝试。若插入期间租约已到期，整批建议和状态更新回滚。

旧工作线程即使恢复并返回成功，也不能发布建议、改写作业或恢复租约。后台没有任何直接改任务的入口，仍只生成 PENDING 建议。

所有领取、续租、完成、到期与 next_run_at 使用 PostgreSQL clock_timestamp()，避免不同应用实例的系统时钟差异影响租约。

## 自动重试与恢复

自动重试：超时、连接错误、429、上游 5xx、中断和临时数据库保存故障。指数退避：

    min(retryMax, retryBase × 2^(attempt-1) + 有界随机抖动)

默认约 2–2.5 秒、4–5 秒，最多 3 次尝试（包括第一次）。

不自动重试：鉴权失败、未配置模型、服务拒绝请求、不合法/截断输出、错误证据、非法任务引用、配置与入队时不同等。它们会立即转 FAILED，保留安全错误码供人工处理。

每次轮询先恢复一批已过期 RUNNING 作业：标记旧尝试 EXPIRED，清除旧令牌；有余量则退避后重新领取，否则进入 FAILED。进程重启无需扫描日志或重建内存列表，未完成作业直接从数据库恢复。

优雅关闭时停止领取，将仍持有的作业标记 ABANDONED 并重新排队，取消本机调用。硬中断没有清理回调，也能在租约到期后接管。

执行语义是 at-least-once，成功建议入库有令牌和事务保护。进程可能在供应商已处理请求、结果尚未入库时崩溃，因此不能保证供应商只计费一次；外部模型可能被重复调用，旧结果不会重复入库。

同一轮冻结 provider、model、prompt_version。工作实例配置与它们不一致时结束该轮并提示人工重试；滚动部署时应使用相同模型/提示配置，或先处理完队列。密钥轮换无需改变这些公开配置。

## 保留的业务机制

- 文档去重仍是项目 + 换行规范化原文哈希 + 记录日期 + 时区；重复导入不会新增作业。
- 建议和来源引句仍由确定性校验器校验，任务 ID 只能来自入队时的当前项目快照。
- 模型不能写任务状态或自行应用建议。
- 人工审核事务、相同建议重复确认返回首次结果、旧版本 409 后保持 PENDING 的逻辑未改动。
- UPDATE 基准版本来自入队快照；即使排队期间任务已经改变，也必须重新核对当前值后提交，不能自动覆盖。

## 接口与页面

- POST /api/projects/{id}/documents：HTTP 202，返回已经持久化的文档和作业，通常初始为 QUEUED。
- POST /api/documents/{id}/extract：HTTP 202；FAILED 才创建新 generation，活跃或成功文档直接返回原记录。
- GET /api/documents/{id}：每轮作业及 attempts，按 generation/attempt_no 排序；不向前端返回租约令牌。
- 项目列表增加 active_job_count，页面在有活跃作业时更新统计。
- 文档列表与审核详情轮询后台状态；FAILED 才显示“重新抽取”，RETRY_WAIT 显示自动重试时间，不要求重复提交。

## 配置

| 环境变量 | 默认值 | 含义 |
| --- | ---: | --- |
| TRACEFLOW_QUEUE_ENABLED | true | 本实例是否运行工作线程；false 仍可接收入队，需另有工作实例 |
| TRACEFLOW_QUEUE_CONCURRENCY | 2 | 本实例并发数，1–8 |
| TRACEFLOW_QUEUE_MAX_ATTEMPTS | 3 | 新一轮作业的尝试上限，1–10 |
| TRACEFLOW_QUEUE_POLL_MS | 500 | 领取及恢复轮询间隔 |
| TRACEFLOW_QUEUE_LEASE_SECONDS | 30 | 租约长度，5–300 秒 |
| TRACEFLOW_QUEUE_HEARTBEAT_MS | 5000 | 续租间隔，必须小于半个租约 |
| TRACEFLOW_QUEUE_RETRY_BASE_MS | 2000 | 指数退避起点 |
| TRACEFLOW_QUEUE_RETRY_MAX_MS | 60000 | 最大退避，包含抖动 |

上限在入队时保存，修改配置不会偷偷修改现有作业的尝试预算。模型配置沿用 P3。测试可以禁用调度器并显式驱动作业；产品默认始终异步。

## 升级与验证

V3 迁移增加 generation、工作线程/续租字段和 extraction_attempt 表。P3 已完成作业保留；P3 人工尝试顺序转为 generation，每个历史作业补一条历史尝试。P3 遗留的 RUNNING 安全转 QUEUED。

升级前先停止 P3 进程，再让 Flyway 迁移。不要让不支持租约的 P3 进程与 P4 同时处理同一数据库。

    mvn -s .mvn/central-settings.xml test
    ./scripts/Smoke.ps1

Smoke 脚本现会等待后台终态，再验证真实模型、文档去重、人工确认、冲突重审和历史。不会用固定延迟假定模型已经完成。
