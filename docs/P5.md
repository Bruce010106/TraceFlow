# P5：登录与项目权限

P5 使用 Spring Security 会话认证。账号存入 PostgreSQL，密码使用 BCrypt（cost 12），浏览器只持有 HttpOnly、SameSite=Lax 的 JSESSIONID。会话空闲30分钟过期；服务重启后需要重新登录，数据库队列和项目数据保留。不会在 localStorage 保存密码或登录令牌。

## 接口契约

所有业务 `/api/**` 接口必须登录。仅健康检查、CSRF 初始化、注册和登录允许匿名。前端静态页面可访问，业务数据仍经过认证。所有非安全方法（POST/PATCH/PUT/DELETE，含登录/注册/退出）必须提供当前会话的 `X-CSRF-TOKEN`。

1. `GET /api/auth/csrf` → 200 `{token,headerName}`，保存响应的会话 Cookie。
2. `POST /api/auth/register` → 200 `{id,username}`，请求 `{username,password}`，注册后不自动登录。
3. `POST /api/auth/login` → 200 `{id,username}`，相同请求字段；轮换会话 ID 和 CSRF token。登录后重新 GET csrf。
4. `GET /api/auth/me` → 200 `{id,username}`；未登录401。
5. `POST /api/auth/logout` → 200 `{loggedOut:true}`；销毁会话、清除 Cookie，下次写入前重新 GET csrf。

用户名3–40位，只允许字母、数字、`_`、`-`，首位为字母或数字，保存为小写；密码12–64字符且 UTF-8 不超过72字节。用户名重复409 `USERNAME_TAKEN`；登录失败401 `INVALID_CREDENTIALS`，不区分账号不存在与密码错误。请求字段错误400；CSRF 缺失或失效403 `CSRF_INVALID`。前端不会自动重放任何写请求。

| 项目角色 | 查看文档、建议、任务、历史和成员 | 导入/重试/审核/任务更新 | 管理成员 |
|---|---|---|---|
| OWNER | 是 | 是 | 是 |
| EDITOR | 是 | 是 | 否 |
| VIEWER | 是 | 否 | 否 |

创建项目时，创建人原子成为唯一 OWNER。`GET /api/projects` 仅返回当前用户加入的项目，并增加 `role`。只读成员写入403 `FORBIDDEN`；非成员访问项目或其文档、建议、任务、历史均404 `NOT_FOUND`，与不存在资源使用相同错误正文。权限来源为数据库成员关系，不能由请求里的用户 ID、Header 或前端状态决定。

- `GET /api/projects/{id}/members` → 200 `[{id,username,role}]`。
- `PUT /api/projects/{id}/members/{username}`，请求 `{role:"EDITOR"|"VIEWER"}` → 200 最新成员列表。只能添加已经注册的账号；重复设置相同角色无额外效果。
- `DELETE /api/projects/{id}/members/{username}` → 200 最新成员列表；重复移除同样成功。
- 所有者不能移除自己或修改自己的角色（409 `OWNER_REQUIRED`），也不能将另一个成员设置为 OWNER。所有权转让不在本阶段范围内。

现有接口的202入队、人工审核、409版本冲突、文档去重与审核重放语义保持不变。**先校验当前权限，再返回幂等结果**，已应用建议也不能绕过撤权。

## 一致性与审计

项目写操作先锁项目行，再查询当前成员权限。角色变更、移除成员也锁同一项目行；写事务如果等待了撤权事务，拿到锁后重新查权限。已开始并先获得项目锁的合法写入可以完成，撤权在其提交后生效。

后台 Worker 只消费数据库中的持久化作业，不依赖用户会话。导入者退出或被撤权后，已入队的作业仍可生成 PENDING 建议；后续审核仍检查审核人的当前权限。租约、续租、过期恢复、重试预算及 fencing 不变，模型不会直接改任务。

新增 `app_user`、`project_member`；文档保存 `created_by`，建议保存 `reviewed_by`，任务历史保存 `actor_user_id`，历史接口增加 `actor_username`。旧记录的身份字段为 null，前端标记为“历史记录”，不补造历史操作人。

## 已有项目迁移

V4 不给任何新注册账号自动分配旧项目。使用持久库时：

1. 正常启动并在网页注册自己的账号。
2. 停止服务，用同一个数据库设置环境变量后启动一次：

```powershell
$env:TRACEFLOW_LEGACY_OWNER_USERNAME = '你的已注册用户名'
./scripts/Start-Backend.ps1
```

3. 该本机操作仅认领**没有任何成员**的项目，不改变已有项目归属。退出后删除环境变量，再正常启动：

```powershell
Remove-Item Env:TRACEFLOW_LEGACY_OWNER_USERNAME
./scripts/Start-Backend.ps1
```

重复执行不会重复授权；账号不存在则启动失败且不分配项目。临时演示库退出即丢弃，无需认领。

## 运行与验证

`./scripts/Smoke.ps1` 默认创建独立随机 QA 账号和项目，完成登录、真实/模拟抽取、审核、去重、版本冲突、历史与退出。也可以通过本机环境变量 `TRACEFLOW_SMOKE_USERNAME`、`TRACEFLOW_SMOKE_PASSWORD` 使用现有账号；脚本不输出密码。QA账号和项目保留在对应演示库，临时库退出后丢弃。

自动化回归包含真实 PostgreSQL、实际 Spring Security 过滤链，以及真实登录产生的会话。安全测试覆盖匿名、只读、非成员、撤权、CSRF、会话轮换、退出、审计、旧项目认领与有权限用户的完整审核流程；P0–P4 回归继续验证幂等、版本冲突、队列、租约、重试及故障恢复。

本阶段面向本机 MVP，尚不包含密码找回、邮箱验证、MFA、登录限流、所有权转让或跨实例共享登录会话。以后对外部署时应在 HTTPS 下设置 `TRACEFLOW_SESSION_SECURE=true`，并按实际开放方式补上账号滥用控制。

参考：[Spring Security 会话管理](https://docs.spring.io/spring-security/reference/6.5/servlet/authentication/session-management.html)、[CSRF](https://docs.spring.io/spring-security/reference/6.5/servlet/exploits/csrf.html)。

可重复运行的最小 HTTP 契约回归：

```powershell
postman collection run postman/collections/p5-auth.postman_collection.json --no-report-events
```

集合只使用本机目标、随机 QA 凭据和独立新项目，不绑定或发布 Postman 云工作区。完整角色和资源矩阵由 `SecurityIntegrationTest` 覆盖。
